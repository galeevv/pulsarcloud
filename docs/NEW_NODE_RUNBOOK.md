# Добавление новой ноды — рунбук

Два типа нод, два эталона:

| Тип | Эталон | Как устроено |
| --- | --- | --- |
| `cdn` («LTE») | Польша LTE | Клиент → CDN-домен (edge российского CDN) → origin-домен (наш VPS, nginx на 443) → xray на loopback. Секретный путь уходит в туннель, всё остальное отдаётся сайтом-прикрытием. |
| `selfsteal` | Финляндия | Клиент → домен ноды напрямую. 443 занимает xray (VLESS + XHTTP + Reality), `target` Reality — локальный nginx с настоящим сертификатом. Кто не прошёл аутентификацию, видит настоящий сайт. |

Скрипты: `deploy/nodes/new-node.sh` (запускается **на ноде**) и `deploy/nodes/new-node-panel.py` (запускается **на pulsar2**). Оба идемпотентны, оба спрашивают параметры интерактивно, если не передать аргументами.

---

## 0. Что подготовить заранее

**VPS:** Ubuntu 24.04, 1–2 vCPU / 2 ГБ / 20+ ГБ, открытые 80 и 443. Для CDN-ноды география origin почти не важна (клиенты идут на edge), для прямой ноды — важна и география, и «чистота» IP: проверь его доступность из РФ **до** настройки.

**Домены.** Для `selfsteal` нужен один, для `cdn` — два:

| Тип | Запись | Значение |
| --- | --- | --- |
| оба | `<домен>` A | IP ноды |
| cdn | `<cdn-домен>` CNAME | технический домен CDN-ресурса |
| cdn | `_acme-challenge.<cdn-домен>` TXT | из Certificate Manager облака |

Домен бери нейтральный, не связанный с брендом сервиса, whois privacy, не российская зона и не российский регистратор. Отдельный домен на каждую ноду: бан одного домена не должен уносить остальные.

**Для `cdn` — сторона облака** (Yandex Cloud; VK Cloud настраивается аналогично):

1. Certificate Manager → сертификат от Let's Encrypt на **CDN-домен** (не origin), проверка DNS → добавить TXT-запись, подождать 20–30 минут.
2. Cloud CDN → создать ресурс: источник — **origin-домен**, протокол к источнику HTTPS; доменное имя ресурса — CDN-домен; сертификат из шага 1; **значение заголовка Host — origin-домен**; кэширование выключено; сжатие выключено; выгрузка логов и экранирование выключены; HTTP/2 включён.
3. Из карточки ресурса взять технический домен → прописать CNAME.

Ресурс собирается 5–30 минут. Проверка: `curl -sI https://<cdn-домен>/health` → `200` и заголовок `Cache-Host: yccdn-…`.

**Доступ:** на новом VPS положить ключи (скрипт `bootstrap-node-access.sh`, либо вручную ключ `pulsar-infra` в `/root/.ssh/authorized_keys`).

## 1. Нода

```bash
scp -i ~/.ssh/pulsar_infra_ed25519 deploy/nodes/new-node.sh root@<IP>:/root/
```

CDN-нода:

```bash
ssh -t -i ~/.ssh/pulsar_infra_ed25519 root@<IP> 'bash /root/new-node.sh --type cdn --domain <origin-домен> --cdn-domain <cdn-домен>'
```

Прямая нода:

```bash
ssh -t -i ~/.ssh/pulsar_infra_ed25519 root@<IP> 'bash /root/new-node.sh --type selfsteal --domain <домен>'
```

`ssh -t` обязателен, если хочешь видеть вопросы и подтверждения. Без `-t` терминала нет: скрипт возьмёт значения по умолчанию, а на подтверждениях сочтёт ответ утвердительным. Полностью неинтерактивно — добавь `--yes`.

Скрипт: обновит пакеты, поставит зависимости, сделает swap, включит BBR и подымет буферы, поднимет лимиты, установит docker, настроит ufw (2222 — только с IP панели), сгенерирует сайт-прикрытие, выпустит Let's Encrypt с автопродлением и хуком перезагрузки nginx, соберёт nginx под выбранный тип и поднимет remnanode.

На шаге remnanode он остановится и попросит ключ панели — это нормально:

```bash
scp -3 -i ~/.ssh/pulsar_infra_ed25519 root@<IP-живой-ноды>:/opt/remnanode/.env root@<IP-новой>:/opt/remnanode/.env
```

После этого запусти скрипт **ещё раз** той же командой — он продолжит с этого места.

> Ключ берётся только с живой ноды. `GET /api/keygen` отдаёт другой, ротируемый ключ, и нода с ним к панели не подключится.

Сайт-прикрытие скрипт генерирует болванкой и **не перезаписывает**, если `index.html` уже есть. Свой сайт заливай в `/var/www/<домен>/` — до или после, безразлично.

## 2. Панель

```bash
scp deploy/nodes/new-node-panel.py pulsar2:/opt/pulsar/
```

Сначала посмотреть конфиг и проверить его ядром, ничего не меняя (`-t` — чтобы скрипт мог задать вопросы):

```bash
ssh -t pulsar2 'set -a; . /etc/pulsar/pulsar.env; set +a; python3 /opt/pulsar/new-node-panel.py --dry-run'
```

Потом создать (аргументы можно не передавать — спросит):

```bash
ssh -t pulsar2 'set -a; . /etc/pulsar/pulsar.env; set +a; python3 /opt/pulsar/new-node-panel.py --type cdn --name "Poland-3" --ip <IP> --domain <origin> --cdn-domain <cdn> --country PL --remark "🇵🇱 Польша | LTE-2"'
```

Скрипт создаст профиль с инбаундом, ноду, host с `fingerprint: edge`, положит инбаунд в обкаточный сквод, сохранит id в `/root/node-<имя>-ids.json` и сделает бэкап состояния панели в `/opt/pulsar/backups/`. Боевым скводам инбаунд не выдаётся.

Для `selfsteal` он сам сгенерирует **свои** x25519-ключи и два shortId. Переиспользовать ключи или `dest` между нодами нельзя: на общем Reality-конфиге РКН однажды забанил нам две ноды одновременно.

## 3. Проверка

На ноде должен открыться порт xray — сразу после того, как инбаунд попал в сквод:

```bash
ssh -i ~/.ssh/pulsar_infra_ed25519 root@<IP> 'ss -ltn | grep -E ":4444|:443"'
```

Дальше по типу:

```bash
curl -sI https://<cdn-домен>/health
```

для CDN-ноды (ждём `200` + `Cache-Host`), либо для прямой ноды — открыть `https://<домен>` в браузере: должен показаться сайт-прикрытие с валидным сертификатом.

**Тест реальным трафиком.** Добавь тестовому пользователю обкаточный сквод, обнови подписку в клиенте и проверь **из РФ** — из-за границы белые IP российских CDN и работа DPI не проверяются в принципе.

Сквозной тест со своей стороны (клиент запускать на **другой** ноде, не на боевой):

```bash
ssh <нейтральная-нода> 'docker run -d --rm --name probe --network host -v /root/client.json:/c.json --entrypoint xray remnawave/node:latest run -c /c.json; sleep 6; curl -s --socks5-hostname 127.0.0.1:10808 https://ifconfig.me; docker rm -f probe'
```

где `client.json` — конфиг из подписки тестового пользователя. Egress должен совпасть с IP новой ноды.

## 4. Выдать пользователям

```bash
ssh pulsar2 'bash /opt/pulsar/attach-inbound.sh <INBOUND_UUID> PulsarLTE'
```

CDN-ноды идут только в `PulsarLTE`. Прямые ноды — в `Pulsar` и `PulsarLTE`.

---

## 5. Откат

| Что откатить | Как |
| --- | --- |
| Убрать у пользователей | снять инбаунд со сквода в UI, либо восстановить состав из `state-before.json` в бэкапе |
| Отключить ноду | `POST /api/nodes/<uuid>/actions/disable`, либо выключить host (`isDisabled`) |
| Снести полностью | удалить host → ноду → профиль (в этом порядке), затем на ноде `docker compose down` в `/opt/remnanode` |

Бэкап состояния панели перед изменениями лежит в `/opt/pulsar/backups/remnawave-newnode-<ts>/`.

## 6. Если что-то не работает

| Симптом | Причина и что делать |
| --- | --- |
| Клиент пишет «подключено», трафика нет | **Первым делом проверь `fingerprint` на хосте: должен быть `edge`.** `chrome` не проходит российский DPI — на этом уже терялся час. Дальше — параметры хоста должны совпадать с инбаундом до последнего поля. |
| Порт xray не слушает, в логах тишина | Инбаунд не попал ни в один сквод — панель такой инбаунд на ноду не отдаёт. |
| Нода в панели `disabled` после правки | Частичный `PATCH /api/nodes` молча выставляет `isDisabled`. Лечится `actions/disable` → `actions/enable`. Транспорт меняй правкой профиля **без переименования инбаунда**, иначе меняется UUID и рвутся привязки. |
| Через CDN 4xx/5xx, а origin отвечает 200 | Настройки ресурса: Host-заголовок должен быть origin-доменом, кэш и сжатие выключены. |
| Туннель виснет секунд на 15 | Буферизация: `noSSEHeader: false` на обеих сторонах, а в nginx `proxy_buffering off`, `X-Accel-Buffering: no`, `Cache-Control: no-store, no-transform`. |
| `nginx -t` падает на `http2 on` | В nginx 1.24 (Ubuntu 24.04) такой директивы нет — только `listen … ssl http2`. |
| Reality не пускает, в access-логе сайта видны браузерные запросы в момент коннекта | Клиент не прошёл аутентификацию и был отдан на `target`. Проверь `publicKey`/`shortId` у хоста и что `target` реально отдаёт TLS 1.3 + ALPN h2. |
| Логи xray | Внутри контейнера: `docker exec remnanode tail -f /var/log/xray/current`. `docker logs remnanode` показывает только обвязку ноды. |

Не гоняй нагрузочные тесты и `docker pull` на боевой ноде: это одновиртуальные машины, и просадка видна пользователям. Для тестов есть обкаточная нода.
